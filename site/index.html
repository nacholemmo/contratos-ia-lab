El trabajo pesado está antes de firmar

Para alquilar, la inmobiliaria junta y revisa los papeles del inquilino y de los garantes. Llegan como fotos sueltas por WhatsApp o mail: el frente y el dorso del DNI por separado, recibos de meses salteados, títulos de varias páginas, alguna foto borrosa, repetida o de otra cosa. Alguien tiene que ordenarlas, ver de quién es cada una y revisar que todo cierre.

La IA sugiere, el código decide y una persona confirma

Al que arma el legajo no le sirve un chat: necesita un legajo ordenado en el que pueda confiar. Por eso la IA solo hace lo que requiere leer, y todo lo que es una regla o una cuenta lo hace código con tests.

Lo que hace la IA

  • Clasifica cada foto: DNI, recibo, garantía, contrato, seguro u otra cosa.
  • Junta las fotos que forman un mismo documento, como el frente y el dorso.
  • Asigna cada documento a una persona y su rol.
  • Extrae los datos, cada uno con la evidencia de dónde salió.

Lo que hace el código

  • Calcula los cruces y las alertas.
  • Hace todas las cuentas de dinero y fechas, siempre con Decimal.
  • Detecta los faltantes según lo que pide la inmobiliaria.
  • Nada queda como definitivo sin que una persona lo confirme.

synthetic/fotografiado.py

def ingreso_insuficiente(alquiler: Decimal, netos: dict[str, list[Decimal]]) -> bool:
    ultimos = [lista[0] for lista in netos.values() if lista]
    if not ultimos:
        return False
    return sum(ultimos, Decimal(0)) < alquiler * INGRESO_MINIMO_EN_ALQUILERES

Un cruce son cuatro líneas de código, no una pregunta al modelo.

Se toma el neto del recibo más reciente de cada inquilino y se suman, porque alquilan juntos. Si no hay recibos, no hay alerta: es un faltante. El primer intento sumaba los tres recibos de cada persona y los comparaba con un mes de alquiler; no fallaba, daba una alerta equivocada. Lo atrapó un test de un centavo de diferencia.

Para medirlo, legajos generados sin IA a partir de una semilla

Para evaluar una IA que lee documentos, los documentos de prueba no los genera una IA. Un generador determinístico arma cada legajo a partir de una semilla: el mismo número produce los mismos datos, las mismas fotos y la misma respuesta correcta, byte a byte. Así se sabe de antemano cómo tiene que quedar cada legajo.

synthetic/source.py

def derive(self, label: str) -> "Source":
    # Se usa sha256 y no hash(), porque hash() de un str
    # cambia entre ejecuciones de Python.
    digest = hashlib.sha256(f"{self.seed}:{label}".encode()).digest()
    return Source(int.from_bytes(digest[:8], "big"))

Cada parte del legajo saca su azar de una sub-fuente propia.

Así, sumar una página o una intrusa no cambia el resto del legajo. Un detalle que hace la diferencia: las fotos se renombran después de mezclarlas. Si conservaran la numeración del legajo ordenado, IMG_4821, IMG_4822… delatarían qué fotos van juntas, y el clasificador podría acertar sin mirarlas.

El error estaba en la definición, no en el modelo.

El LLM fallaba con títulos que dicen "constancia de titularidad de inmueble" y nunca "garante", porque la definición pedía el título "de un garante". Describir lo que se ve en el documento arregló lo mismo que 6 ejemplos, con 3,3 veces menos costo. Y es el único enfoque barato que lee fotos, que es justo lo que entra al servicio.
